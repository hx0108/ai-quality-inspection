# 注册页多项目归属设计

## 目标

项目人员在账号注册时可选择一个或多个所属项目。注册完成后，用户立即拥有全部已选项目的访问范围，同时维持既有单项目兼容字段。

## 已确认规则

- “所属项目”为必填，至少选择一个项目。
- 用户勾选顺序中的第一个项目作为默认项目。
- `users.project_id` 与响应中的 `project_id`、`project_name` 保存/返回默认项目，兼容现有单项目流程。
- `user_projects` 写入全部已选项目，登录响应的 `projects` 返回完整列表。
- 旧版只提交 `project_name` 的注册请求继续可用。

## 界面设计

注册表单中的“所属项目”字段点击后打开底部多选弹层。弹层显示全部可选项目，每项提供复选框，并显示“已选择 N 个项目”；用户点击“确认选择”后回到表单，字段区域显示所选项目标签，第一个标签标记为“默认”。

## 接口与数据流

前端注册提交新增 `project_ids` 和 `project_names`，同时继续提交第一个项目的 `project_id` 与 `project_name`。后端优先处理 `project_ids`，按请求顺序查询项目、拒绝不存在的 ID，并将第一项设置为默认项目；当 `project_ids` 未提供时，维持现有按单个 `project_name` 注册的处理方式。

## 验证

- 后端测试覆盖多项目注册成功、默认项目为第一项、全部关联落库与响应返回。
- 保留现有单项目注册测试以验证兼容性。
- 运行后端认证测试与前端生产构建。
- 发布后通过线上静态资源与接口可用性检查确认上线。
